## Summary

The Cloud Beast is a boss that hovers between six arena points and alternates between idling and one of six attacks: a close-range shock, a combat fidget, a single air-flow gust, a rapid series of gusts, a lightning barrage and bouncing bolt balls. Its HP decides one of three stages, and each stage changes the attack weights, cooldowns and speeds. When a band's attack is cooling down, its share of the roll goes to the lightning band instead of being dropped. A second body, the companion (monster row 2, class 10), rides on the boss: the lightning comes from the companion, and the reaction trigger watches it. The hero cannot damage either body: on every tick except those of the reaction state the controller marks both the boss and the companion unhittable, so the hero's swing, shots, Mote objects and charm walks never select them, and during the reaction state they only guard (swings are blocked and quick shots bounce, no damage). The one source of HP loss is the controller's own reply to a reflected lightning beam: a guarding hero with the Fog Mote (item 166) in the shield word, facing the boss from more than about 14 units, sends the beam back, and the boss plays a special-reply state that costs it 20 HP. The fight has no end: when the twelfth reply takes the HP to 0 the shared death hook runs, but the controller's own tail on the same tick puts the boss back in base state 1, so it keeps fighting at 0 HP. During the gust's travel the boss and the companion are not drawn: the beast vanishes from its point, the gust column crosses the arena and the beast reappears at the new point. One more limit applies to the shipped data: the lightning beams work only while their beam effect exists, and that effect definition is missing from the disc, so with the disc's own effect library the lightning is invisible, cannot be blocked or reflected, and the boss never loses HP at all (Lightning, Beam activity). The build guide therefore runs the designed fight with stand-in beam effects. All timings run on the 60 Hz game tick (SPEC-0007). Times given in seconds become ticks = trunc(seconds x 60). The fight is not placed anywhere on the disc and does not occur in normal play (see Placement and reachability); this spec describes the behaviour as it exists in the boot program, for a reimplementation that may still include it.

## Fight AI build guide

### Test setup (recommended)

- Spawn monster type 1, variant 0 (row 1: class 9, 240 HP, radius 3.0, height 3.5, no attack slots) and monster type 2, variant 0 (row 2: class 10, 50 HP, radius 1.175, height 3.5). Spawn both before or on the first tick; the boss looks for the companion every tick until it has one. Spawn exactly one type-2 body.
- Arena: a level that holds the six locators with user ids 101 to 106 (the Juppie arena does; a synthetic ring of six points with position and facing also works). The boss never walks; it is placed on the current point (see Arena movement).
- Hero: either hero, standing still about 20 units from the boss to see the attack cycle; closer than 15 units triggers the shock. Give the hero the Fog Mote (item 166) in the shield word and guard facing the boss to test the reflected beam.
- Stand-in boss rig (satisfies the behavioral rig contract): any skinned creature with at least 12 bones (bone 6 is the gust origin, bone 11 the companion attachment), a main action table of 24 entries (ids 0 to 23) in which every id the controller requests (4, 5, 6, 7, 8, 10, 11, 12, 13, 14, 15, 16, 22, 23) maps to a clip, and clip 14 carrying animation event 32. "Event 32" is the release frame bit 0x20 of the frame-bit table (SPEC-0005, Table B frame bits): it must sit on a frame before progress 0.99, because the controller tests it only while clip 14 is current and not yet done. Clip 11 must last longer than one tick (see Edge cases). Unrequested ids may map to the idle clip. Give it at least one bone hurt capsule of positive length if the guard window of the reaction state is to be tested.
- Model extension (kind key 340). At the end of each gust the original calls two methods of the boss model's extension object without checking that one exists; only characters whose spawn record has kind key 340 (a set of 24 cloud particle emitters on attachment points 9 to 20 of the model, see Placement and reachability) or a Werelupe key (empty methods) have one, and any other spawn reads through an empty reference there (no defined result). Give the test spawn kind key 340. Even then the emitters never appear with the disc's effect library, because their set-up and restart first look up effect 453, which is missing. Default if unresolved (rewrite choice): treat a missing extension as empty methods; a stand-in can attach looping cloud particles to its attachment points and stop or restart them on those two calls.
- Effects (rewrite choice, required for the designed fight). The lightning beams only work while their beam effect exists (Lightning, Beam activity): with the disc's library (definition 447 missing) the beams stay inert, the lightning never hits or reflects, and the boss can never lose HP. Default if unresolved (rewrite choice): bind stand-in definitions so that a started beam is always active: the Undead Draik's ice breath-beam set, 437 in place of 447 and 441 in place of 448 (SPEC-0029 Section 6; blue and white). Recommended authored stand-ins for the rest: 449 gust stream, a pale grey-white looping particle column along the gust ends with alpha from the fade value; 450 ball, a small looping blue-white glowing sprite (radius about 2, the touch radius); 451 burst, a one-shot white-blue spark burst; 454 shock, a looping electric ring scaled to radius 8; 453, 455, 456, 457 cloud emitters, soft grey-white looping puffs (two per attachment point). Effects 430 to 446 nearby are the Draik and other boss sets and may be borrowed for colour.
- Stand-in companion rig: a small separate skinned body with a pose point (attachment) at index 1 and a main action table of 24 entries (it receives every request of the boss; any id may map to its idle clip).
- Stand-in boss model (rewrite choice): no model exists. Recommended look, from the clues (kind-340 cloud emitters on 12 attachment points, radius 3.0 and height 3.5, a carried lightning source): a floating cloud body of soft grey-white particles around a simple skinned core with at least 21 attachment points, hovering on its point, with the companion as a small glowing storm orb held at bone 11. Any donor rig with enough bones and clips works (Placement and reachability, Behavioral rig contract).
- Default if unresolved (rewrite choice): clip lengths are not on the disc. Use these lengths in ticks at play rate 1.0 for the time from clip start to progress 0.99: id 5 fidget 90; id 6 gust wind-up 60; id 7 gust 60; id 22 gust run-out 60; id 10 lightning recovery 60; id 11 shock start 30; id 13 shock end 45; id 14 bolt cast 90 with event 32 at tick 45; ids 15 and 16 reply 90; id 4 idle, 8 lightning, 12 shock loop and 23 reaction are looping or held (no completion gate). A clip requested on tick t is current from tick t + 1. A gated phase ends on the first tick on which the current clip's progress is at least 0.99. At a play rate m the length is the default divided by m (gust ids 7 and 22 use the stage multiplier 1.25, 2.0 or 3.0). These are rewrite choices, not original values. The only constraint the code gives: a clip 7 of at least 50 ticks lets a stage-1 gust reach its full length of 10 (the charge caps after 40 current ticks; at speed 1.25 a 60-tick clip is current for 48); clips 11 and 14 must last more than one tick (Edge cases). If real clips are authored, their done ticks follow the common gate rule: at play rate 1.0 a clip of speed byte S advances 1 / (2S) key per tick from its request tick, the controller reads progress before the animation pass, and a one-shot clip of F keys passes the 0.99 gate on tick request + 2S(F - 1) + 1, one tick earlier when F is at least 50 / S (SPEC-0005, Clip progress); at the stage multipliers 1.25, 2.0 and 3.0 the speed is multiplied by the same factor and the tick is found by the same stepping.

### Initial values (tick 0, High)

State 0 (idle), sub-state 0, stage 1, hesitation H = random integer 60 to 120 ticks (stage-1 range, drawn before tick 0, so the first decision falls on tick H − 1, 59 to 119), air-flow cooldown 180 ticks (clear from tick 179, so the first decision can never be air-flow or rapid air-flow), lightning and bouncing cooldowns 0, gust fade value 128, hit latch 0, balls spawned 0, rapid count 0, current arena point 0 (locator 101), next point none, previous point none, charge 0, companion none, HP 240 of 240. The sub-timer, rapid count, ball counter, reaction hold and previous point are not set at start; none is read before it is written, so a rewrite sets them to 0 (previous point none). All six locators are looked up once at start; a missing one prints a warning and leaves an empty point (see Edge cases). The three beam and stream effect objects and the ball effect handles are created at start. The hero used by every test is the current selected hero, read again on every tick.

### Per-tick order (High)

State numbers: 0 idle, 1 shock, 2 fidget, 3 air-flow, 4 rapid air-flow, 5 lightning, 6 bouncing bolt, 7 special reply, 8 reaction.

1. Timers: hesitation, the three cooldowns and the sub-timer each drop by 1 while above 0.
2. The boss's hold word is cleared, its body-push flag is cleared (the boss neither pushes nor is pushed by other bodies), its time scale is reset to 1.0 and the gust fade flag is cleared.
3. Stage from HP (Each tick, in order).
4. Reaction check in every state except 3 and 4 (Reaction trigger). A true trigger sets state 8 and stops both beams; the handler of the interrupted state does not run on this tick.
5. Decide (idle only) and the shock check (Deciding).
6. Run the state handler (States).
7. Arena movement, gust-stream draw, ball update, companion step (Companion).
8. Tail: when the state is 8, the boss and the companion are set to base state 20 (guard stance) and nothing else is written; in every other state the boss and the companion get their invulnerable word set to 1 (never cleared) and are set to base state 1. This write has no guard, so it also undoes a base state 16 written by the death hook earlier in the same tick (Phases and death). Then the debug line, then one tick of waiting.

### Attack chooser (High)

Roll 0 to 100 (inclusive), bands from the stage's weights with the cooldown fall-through rule (Deciding). Weights, stage 1 / 2 / 3: fidget 20 / 10 / 0, air-flow 40 / 30 / 25, rapid 0 / 5 / 15, lightning 40 / 35 / 25, bouncing 0 / 20 / 35. A decision that picks nothing leaves hesitation at 0, so the boss decides again on the next tick; roll 100 and the empty (cooling) bands are the only idle outcomes. A chosen attack redraws hesitation (60 to 120 ticks in stage 1, 30 to 60 in stages 2 and 3), which keeps counting during the attack, so the next decision follows the end of any attack longer than the hesitation without a pause. Cooldowns are drawn only when an attack ends normally.

### Movement (High)

None. The boss is set on the current arena point every tick (ground height from the probe with ceiling 8) and only its facing is steered: weight 0.1 toward the point's facing, except in air-flow (state 3) where it steers toward the next or previous point (Arena movement). It never approaches the hero and ignores reachability, so a hero outside the arena changes nothing except the horizontal-distance gates.

### Hurt rules, hero to boss (High)

- Outside the reaction state the boss and the companion are unhittable and not guarding: the hero's swing, Roberta's shots, Mote objects, charm walks and the random target finder skip them completely. Both stay unhittable for the rest of the run even though the invulnerable word is only rewritten outside state 8.
- In the reaction state both bodies are in the guard stance, so they are still tested by swings and shots but never take damage. A non-power swing is blocked (block effect, counts as landed, no damage) when the dot product of the target's facing and the hero's facing is below the row's Blocking Angle, which is 0 for rows 1 and 2; any other swing does nothing. A power swing and a full-release shot do nothing. A quick shot bounces (no damage). All of this needs bone hurt capsules of positive length, which the missing rig would have to provide.
- The boss loses HP only in the special reply (20 per reply through the shared HP subtraction, no doubling, no hit reaction). The reply needs active beams, so it exists only with beam effects present (stand-ins); with the disc's library the boss stays at 240 HP and stage 1 for good (Beam activity). Stage 2 begins when hp% drops below 66 (HP 158 or less), stage 3 below 33 (HP 79 or less); the twelfth reply reaches HP 0, which does not end the fight (Phases and death). Healing does not exist for the boss.
- No block, dodge, counter or hit-stun exists on the boss side, and nothing resets on a stage change: each parameter is read where it is used (Edge cases).

### Companion role in each attack (High)

Idle, shock, fidget, gust, bouncing and reply: none beyond riding bone 11, facing the hero and mirroring the boss's animation requests; during the gust travel it is hidden together with the boss. Lightning: every beam starts at the companion's pose point 1, so the fire phase needs the companion. Reaction: Roberta's shot test uses a sphere of radius 5 at the companion's pose point 1; Tor's test uses the boss. Every tick the hero's forced lock-on target is set to the boss while the companion exists.

### Phases and death

Stage changes are the only phases (Each tick, in order) and reset nothing. The boss cannot die (High). The reply that takes the HP to 0 sets the HP to 0 and runs the shared death hook (base state 16, the drop and Neopoint steps, the disappear countdown, statuses cleared; SPEC-0029 Behavior 34), then the reply roll of the same handler picks idle, air-flow or rapid air-flow, and the tail of the same tick writes base state 1 (and the invulnerable word) on the boss. The base-state setter has no guard, so the shared update steps the controller again on the next tick and the corpse step never runs. The boss fights on at HP 0 in stage 3 (hp% 0). Each later reply finds 20 not below 0 HP, keeps the HP at 0 and runs the death hook again. The hook's drops repeat: on the first lethal reply the boss drops its carried item (if any) or else its spawn record's drop entry, and its carried Neopoints; on every later lethal reply it drops the spawn record's drop entry again (the carried item and Neopoints were cleared the first time). A test spawn with no drop entry and no carried Neopoints drops nothing. The hook also sets the 510-tick disappear countdown, which never counts because the base state is never 16 when the shared update runs, and clears the status words. What the player sees on the lethal tick: the reply clip ends, any drops appear at the boss, the monster health bar (shown for 10 s by the reply) reads 0, and the boss carries on with idle, a gust or a rapid gust. There is no defeat scene, reward or arena exit (Placement and reachability). The companion is never affected. There is no check for the hero's death: the cycle continues against a dead hero, whose damage calls do nothing.

Ending the fight (rewrite choice, not original behavior). The original has no ending. Default if unresolved (rewrite choice): reproduce the endless fight for fidelity. A rewrite that wants a playable ending can add one with the smallest change: once the HP is 0, skip the tail's base-state and invulnerable writes for the boss on that tick, so the shared death hook's base state 16 stands; the shared update then no longer steps the controller and runs the corpse step with its 510-tick countdown instead (SPEC-0029 Behavior 34). Stop both beams and leave live balls to expire. Set the companion to base state 16 on the same tick (or remove it). Label any such ending in the rewrite as an addition.

### Edge cases for implementers

- Unhittable after tick 0: the invulnerable word is set on the first non-reaction tick and never cleared; the reaction state does not clear it.
- The idle outcome of a decision does not redraw hesitation, so an idle roll repeats on the next tick.
- Entering the shock does not reset hesitation either; after the shock the boss decides on the next tick.
- Cooldowns are drawn at the end of an attack, not at its start, and not at all when the reaction interrupts it.
- The reaction check does not run in air-flow or rapid air-flow, but runs in the special reply and can cancel it before its damage.
- The gust hit and the beam hits use latches (once per decision; counter multiples of 60), not timers.
- Companion lookup keeps the last matching body, runs only until one is stored, and is never repeated.
- The companion's animation speed copy has no lasting effect (Companion), so the companion's clips run at their own rate even while the boss's gust travel step freezes at speed 0.
- A lethal reply does not stop the controller: the tail of the same tick writes base state 1 over the death hook's 16, and the boss fights on at HP 0 (Phases and death).
- First decision on tick H − 1, not H (hesitation is drawn before tick 0 and counted down before deciding). Later decisions fall exactly h ticks after the deciding tick.
- The reaction hold is set on the entry tick; the reply roll comes on the 91st tick after the last tick the trigger was true.
- If the reaction trigger is true on the very first tick, the invulnerable word keeps its creation value 0 until the first non-reaction tick, so in that one window both bodies are hittable and guarding (a power swing can then reach the shared take-hit). Reproduce; it cannot happen again later.
- The shock's sub-step 0 advances only on a tick when clip 11 is current and not done. A clip 11 that is already at progress 0.99 on its first current tick stalls the shock (no timer, no damage, no exit) until the reaction trigger moves the boss to state 8; stand-in clips must be longer than one tick.
- Beam activity: a beam's set call does nothing unless the beam is active, and a beam is active only while the start effect of its definition exists. Without beam definitions (the disc's library) the drawn length stays 0 forever, so there is no wall sweep, no full-extension, no block, no reflect and no special reply (Lightning, Beam activity). With stand-in definitions every start makes the beam active at once.
- Drops at HP 0 repeat on every lethal reply (the spawn record's drop entry each time; the carried item and Neopoints only the first time).
- The fidget choice clears the hit latch but not the sub-state word; the bouncing choice clears the latch and the ball counter but not the sub-state word. Neither state reads the sub-state, so no behavior changes.
- The shock effect is not stopped when a reaction cuts the shock short (only sub-step 2 stops it); it stays started until the next shock moves and restarts it. Whether it is still visible depends on the missing definition 454.
- Gust travel hides both bodies: from the tick clip 7 ends through the last travel tick neither the boss nor the companion is drawn, and the boss's cloud emitters are stopped; they restart when the run-out begins (the emitters exist only when effect 453 exists, so never with the disc's library). The boss is already standing on the new point while hidden. With no companion the original writes the hide flag through an empty reference; a rewrite skips it.
- The gust charge c is reset only after the wind-up, so the second and later rapid cycles start from whatever c the run-out left (at speed 3.0 with a 60-tick clip that is about 5); the column's length peaks at min(10, 0.25 × ticks clip 7 is current).
- The gust speed (1.25, 2.0, 3.0) is written only on ticks when clip 7 or 22 is already current; the request tick plays at 1.0.
- The bouncing state's "fewer balls than the count" branch (cooldown 10 ticks) never fires: the counter counts attempts, not spawned balls.
- The sub-timer is shared by the shock, the wind-up and the fire phase, so a stage-3 lightning chosen soon after a reaction cut a shock or a fire phase short keeps the remaining ticks as its wind-up.
- The reply state shows the boss in the monster health bar (10 s) and plays the common hit spark (effect 222) on its first tick, before the clip is current.

### Timeline test vector (600 ticks, High for the structure; random values flagged)

Hero stands still 20 units away, not guarding, stage 1, companion present, stand-in beam effects present (Test setup; with the disc's library the lightning branch below deals no damage), tick 0 the first controller tick (the start-up and the first loop pass run on the same tick). H = initial hesitation, random 60 to 120, drawn before tick 0; D = H − 1 is the first decision tick (59 to 119). Clip lengths are the defaults of Test setup.

- Ticks 0 to D − 1: idle, shock not triggered (20 is not below 15).
- Tick D: roll r (0 to 100). r 0 to 19 fidget (20/101), r 20 to 99 lightning (80/101; the air-flow band is cooling until tick 179, the rapid band is empty), r 100 idle and rolls again every tick. Example: H = 90 gives D = 89.

Random: the next point (2, 3 or 4 steps around the ring, each 1/3).

## Where it lives on the disc

- The boss's tuning values are 32-bit words in the boot program's data, read at runtime by virtual address (SPEC-0001 gives the fingerprint). They occupy 0x2DA4D0 to 0x2DA617. Each value below gives its address. "int" is a signed 32-bit integer and "float" an IEEE single.
- The six arena points are the level locators with user ids 101 to 106 (the 16-bit id field of the level's locator records, SPEC-0006). If any is missing, the boss cannot move between points. No level on the disc is a Cloud Beast arena (see Placement and reachability).
- The boss's monster row is row 1 of the monster table (monster type 1, variant 0) and its companion's is row 2 (type 2); see SPEC-0029 Layout section 4.
- "Animation n" means entry *n* of the boss's main animation table (SPEC-0005). Every animation request is sent to the companion too when it exists.
- Three effect objects of the boot program's run-time data serve the boss: the gust stream at 0x36B4D0, lightning beam 1 at 0x36B560 and beam 2 (the bounced or reflected beam) at 0x36B5C0. A beam object keeps its drawn length, a target length and a growth limit; see Lightning.

## Behavior

### Placement and reachability (High)

- **Not placed.** The Cloud Beast is not placed anywhere on the disc, so the fight does not occur in normal play. No character record in any region or world pack has its monster type (type 1) or its companion's type (type 2), so no model or animation set is linked to it. No level script spawns it or gives an enemy its class, and no quest entry, movie or fight name refers to it. A child NPC in Brightvale Castle has a pretend-play line about a large cloud creature flying high in the sky; it does not identify the class-9 boss or say where a fight would happen. The Wind Mote's pickup text separately compares the item to a tiny thundercloud; this is item flavor text, not a character or boss reference (SPEC-0024, Table 0; SPEC-0021). Confidence: High for the negative placement findings; neither incidental text establishes a connection to this boss.
- **No encounter-ending logic.** The controller has no hero-death check or explicit victory/defeat transition, cutscene, reward, story update or arena exit. It deals hero damage through shared character methods; when the reflected-beam reply reduces the boss to zero HP, shared death and refresh methods run, but the controller adds no boss-specific aftermath. The death hook places the class-9 actor in base state 16, but the same controller tick finishes its work and its tail writes base state 1, so the shared update keeps stepping the controller and the corpse step never starts (Phases and death; High). Whether an external scene script was meant to end the fight cannot be known. Confidence: High for the controller and shared-state boundary; no placed instance or linked scene exists on the disc.
- **No model on disc.** No model, skeleton or animation set for the Cloud Beast or its companion was found on the disc. Every model set, skeleton and clip bank in the character data is used by a character record of another type, and the boss code needs a bank of at least 24 clips. The monster rows supply behavior and combat parameters but do not identify a model, skeleton or animation table; those are selected by the instantiated character record. No record of type 1 or 2 exists, and no unassigned character-region model, skeleton or clip bank supplies a direct asset binding. The conditional type-0 row-overflow path described above changes the selected row and class but keeps the donor actor's existing rig and animation table; it does not identify the intended Cloud Beast asset. Confidence: High that no unused character-region skeleton or clip bank exists and no type-1/type-2 binding is shipped; Medium-High that no dedicated Cloud Beast model is identifiable in the indexed disc resources. A private packet-space visual check found no recognizable boss mesh among resources 544–575, while resource 528 remains inconclusive because its transforms and material-to-texture bindings are unresolved; these checks cannot rule out an environmental asset or a removed/development-only model.
- **Missing effect definitions.** The controller requests group-3 definitions 447 and 448 when setting up each lightning beam, 449 for the gust stream, 450 for the five ball visuals, 451 for ball expiry/contact bursts, and 454 for the shock effect handle. All six definitions are absent from the disc's effect library. In fact the whole id block 447 to 459 is absent while 430 to 446 and 460 are present: besides the six controller ids it holds 453, 455, 456 and 457, which the kind-340 model extension uses for its cloud emitters (below), and 452, 458 and 459, which nothing requests. So the beast's effects were removed as one block. No other effect library on the disc holds them: the disc has five effect libraries (the shared one, with 666 definitions, and four small level libraries with ids 117 to 130), and none defines any id from 447 to 459. The appearance of all thirteen is therefore unknowable. The missing beam definition is not only cosmetic: a beam object draws nothing of its own (its visuals are the effect instances made from its definition) and its length update runs only while its start instance exists, so with 447 missing both beams stay inert (Lightning, Beam activity). The gust, ball and shock logic do not depend on their effects (the ball slots keep their own alive word, the gust ends live in the boss record), so those attacks work, unseen. Default if unresolved (rewrite choice): for the two beams use the Undead Draik's ice breath-beam definitions (437 for the beam body in place of 447, 441 in place of 448; the same beam-object setup, blue and white, SPEC-0029 Section 6), which also makes the beams active, and author the gust stream, balls, ball burst, shock ring and cloud emitters (Test setup). Confidence: High for the requests, the missing definitions and the beam dependency; unknown for what the missing assets would have looked like.
- **Sound and clip limits.** The controller makes no direct sound-cue call. Although it requests animation indices on the boss and companion, there is no linked type-1/type-2 model, clip bank or animation sound table from which to identify the intended clips or cues. The controller reveals state transitions and event gates but not clip frame counts or playback lengths; the exact frame of ball-spawn event 32 and total durations of animation-gated attacks are not on the disc. Confidence: High for the absence of a linked sound or animation asset in the shipped disc data; the missing clip timing is unrecoverable from this build.
- **Behavioral rig contract (not original art).** A compatible boss rig needs a main skeleton whose bone 6 supplies the gust origin and whose bone 11 supplies the companion attachment point. Its animation bank must provide indexed entries through 23; the controller requests entries 4, 5, 6, 7, 8, 10, 11, 12, 13, 14, 15, 16, 22 and 23. Row 1 (the boss) has default class 9, maximum HP 240 (row field 0x30), radius 3.0 and height 3.5, and no attack slots, so all of its damage comes from the tuning words above. Row 2 (the companion) has default class 10 and HP 50.

Only two levels on the disc hold all six, and both are other bosses' arenas: the Plague Serpent arena, which uses ids 101 to 124 as its anchor points (SPEC-0016), and the Juppie arena, which uses ids 101 to 106 as stage locators (SPEC-0015). In any other level the boss finds no points and stays in place (see Edge cases).
- **Rendering residue.** The boss sets its character fade level to 129. This sends an active character through the composite rendering path but sorts it as opaque; it is not material opacity (SPEC-0003, SPEC-0046). It provides no information about the missing model's appearance. Confidence: High.
- **Story.** No story slot exists for the fight; each Act 3 area has its own boss (SPEC-0049).

### Distances

Every distance test in this spec is the horizontal distance from the boss to the hero (x and z only; height is ignored). The direction used by the shock, reaction and aim tests, and the direction in the reaction dot-product test, is the horizontal unit direction from the boss to the hero. Confidence: High.

### Each tick, in order

1. Count down each active timer by one tick (a value above 0 drops by 1): hesitation, the three attack cooldowns, and the current attack's sub-timer.
2. Clear the gust fade flag and reset the animation speed to 1.0. Also clear the boss's hold word and its body-push flag (so the boss is neither pushed nor pushes other bodies).
3. **Stage**: hp% = trunc(100 × HP / max HP) (the quotient is taken in single precision). If hp% < 33, the stage becomes 3. Otherwise, if hp% < 66, the stage becomes 2. Otherwise the stage is unchanged. The stage starts at 1. Stage 2 never returns to stage 1. Stage 3 drops to stage 2 only when healing leaves it between 33 % and 66 %; at 66 % or above it stays stage 3.
4. **Reaction check**: the trigger is evaluated in every state except air-flow and rapid air-flow, including lightning, the special reply and the reaction itself. If the trigger (below) is true, the boss switches to the reaction state and stops both lightning beams.
5. **Decide**, if idle (below). The decision step does nothing in the special-reply and reaction states.
6. Run the current state.
7. Arena movement (see Arena movement), then draw the gust stream, then update the balls, then attach the companion (see Companion).
8. Tail (High). If the state is 8 (reaction), the boss and then the companion (when it exists) are set to base state 20, the guard stance, and nothing else is written. In every other state the boss and then the companion get their invulnerable word set to 1 and are set to base state 1. Nothing in the controller ever clears the invulnerable word, so both bodies are unhittable from the first non-reaction tick to the end of the run (see Hurt side and Companion).

### Deciding (idle only)

When the hesitation timer reaches 0, the boss makes one decision:

1. Roll r = random integer 0–100 (inclusive). Let F, A, R, L and B be the stage's fidget, air-flow, rapid air-flow, lightning and bouncing weights. Let cA, cL and cB say whether the air-flow cooldown (which also covers rapid air-flow), the lightning cooldown and the bouncing cooldown are running.
2. **Fidget.** If r < F, the boss fidgets. The fidget has no cooldown.
3. **Air-flow.** If r < F + A: if cA is clear, choose air-flow. If cA is running, set base = F. If r ≥ F + A, set base = F + A. (So while cA is running, the air-flow share is removed from the rolls that were inside the air-flow band.)
4. **Rapid air-flow.** If cA is clear and r < base + R, choose rapid air-flow. (With cA clear this is the band F + A to F + A + R.)
5. **Lightning.** Let U = base + R + L. If r < U: if cL is clear, choose lightning. If cL is running, lower U by L and continue.
6. **Bouncing.** If r < U + B and cB is clear, choose bouncing.
7. Otherwise the boss stays idle for this decision. Roll 100 is outside every band (the five weights of each stage sum to 100), so it always leaves the boss idle (1 roll value in 101).

On every choice the boss clears the hit latch (and, for air-flow, rapid air-flow and lightning, the attack sub-state word; the fidget and bouncing choices leave it, and their states never read it; the bouncing choice also clears the ball counter), and it sets the hesitation timer to a random integer number of ticks from trunc(60 × minimum) to trunc(60 × maximum) inclusive, from the stage's range (see Edge cases for the stage-3 range). A lightning choice also sets the wind-up sub-timer (see Lightning).

**Random draws** (High). One shared random stream (the game-wide generator of SPEC-0007). An integer draw from a to b returns a + (n mod (b − a + 1)) for an unsigned 32-bit stream value n, so both end values occur. A real draw from a to b returns a + n × ((b − a) × 2^−32) in single precision; a is reached, and b only through rounding of the largest values of n. This covers the decision roll (0 to 100), the 50 / 25 / 25 rolls (0 to 100), the ring step (1 to 3), the rapid count (3 to 5), the reply coin (0 to 1), the hesitation ticks, the cooldown seconds and the ball blend draws.

Worked values for stage 2 (F 10, A 30, R 5, L 35, B 20):

- Air-flow cooling, lightning ready: rolls 10 to 79 choose lightning; rolls 80 to 99 choose bouncing. Rolls 0 to 9 fidget.
- Lightning cooling, air-flow ready: rolls 0 to 9 fidget, 10 to 39 air-flow, 40 to 44 rapid air-flow, 45 to 64 bouncing, 65 to 79 idle, 80 to 99 bouncing.
- Both air-flow and lightning cooling: rolls 0 to 9 fidget, 10 to 34 bouncing, 35 to 39 idle, 40 to 64 bouncing, 65 to 79 idle, 80 to 99 bouncing. (Medium: the lowered lightning band falls through to the bouncing check; check against a clean build when available.)

If the decision picks nothing, the boss stays idle, and the shock check below applies.

**Shock**: whenever the boss is still idle after deciding (including ticks while hesitation is counting), if the horizontal distance from the boss to the hero is less than 15 units, it starts the shock.

### Reaction trigger

The trigger branches on the hero variant word (0 Tor, 1 Roberta; SPEC-0036), not on an action state. Confidence: High.

- **Tor (variant 0).** The trigger is true when Tor's in-attack test passes, the horizontal distance from the boss to the hero is less than 10 units, and the dot product of the boss's forward direction with the horizontal unit direction from the boss to the hero is greater than 0.5. The in-attack test is the hero's own query (shared with SPEC-0012 and other bosses): it passes while Tor is in action state 13 with an attack sub-state from 2 to 12, or in action states 7 to 11 (the jump states) while his hero word at +0x1508 is 8 or 9 (the meaning of that word is Medium-Low).
- **Roberta (variant 1).** For each of her six shot slots that is armed (SPEC-0036 Hero shot slots), take the segment from the shot's position S to S + 10 × V, where V is the shot's direction times its speed times the run-time frame step (the distance the shot covers in one update). The trigger is true when any such segment touches a sphere of radius 5 centred on the companion's pose point 1. So this mode reacts to Roberta's shots heading at the companion, not to melee volumes, and her own melee does not trigger it.
- **Any other variant value.** The trigger is false.

While the trigger stays true, the reaction state restarts its 1.5 s hold (see Reaction state).

### Arena movement

The boss does not travel between points; it is placed on its current point every tick and only its facing is blended (High).

1. **Position.** The boss's position becomes the current point's position (locator position, SPEC-0006), and its height is then replaced by the ground probe at that spot with ceiling 8 (SPEC-0018 Ground probe: the highest surface below the point raised by 8; 0.0 when the level has no grid there). When the current point changes (end of the gust, air-flow sub-step 1), the boss is on the new point on the next tick.
2. **Facing.** The boss's steer method is called with a weight w and a horizontal unit direction (the facing moves toward the direction by the blend w; w = 1.0 turns it fully). Default: w = 0.1 and the current point's facing vector (the locator facing, SPEC-0006).
3. **Air-flow state only** (state 3; the rapid air-flow state uses the default): the direction is the horizontal unit direction from the boss to a target T, with:
   - sub-step 0: T = the next point, w = 0.1;
   - sub-step 1: T = the next point, w = 1.0;
   - sub-step 2: T = the previous point (the point just left), w = 1.0;
   - sub-step 3: T = the boss's position plus 5 times the current point's facing, w = 0.1 (the same direction as the default);
   - sub-step 4 (one tick): T = 5 times the boss's forward vector taken as a point, w = 0.1 (an artefact; it lasts one tick).

Otherwise draw r2 from 0 to 100: r2 < 50 gives air-flow (chance 2500/10201, about 24.5 %), otherwise rapid air-flow (2550/10201, about 25.0 %). Both attack choices clear the hit latch, reset the sub-state and pick the next point; the rapid choice also draws its count. The roll does not check the air-flow cooldown (High).

Shock sub-steps (High):

- **Sub-step 0**: request animation 11 until it is current; on the first tick it is current and not finished, set a 60-tick timer (the tick rate, 1 s). If it is already finished when first seen current, the step never advances (Edge cases).

### Air-flow and rapid air-flow sub-steps

Both states share sub-steps 0 to 4. The gust is a straight column with two ends, the origin O and the end E, kept in the boss record; it is not aimed at the hero (High). The controller updates the gust-stream handle from O to E on every tick of sub-steps 1 to 3, but its requested particle definition 449 is absent (Placement and reachability). Let B6 be the position of the boss's skeleton bone 6 this tick, f the boss's forward vector and c the charge value.

- **Sub-step 0, wind-up**: animation 6. When it ends, c = 0.
- **Sub-step 1, gust**: animation 7 at the stage's gust speed (1.25, 2.0 or 3.0), set on every tick on which clip 7 is already current (the request tick plays at 1.0; the same holds for clip 22 in sub-step 3). The steps below run only on those ticks. c rises by 0.25 per tick up to 10 (before use, so the first gust tick has c = 0.25). Then O = B6 and E = O + c × f: the column grows out of bone 6 along the boss's facing, which turns fully toward the next point in this sub-step (Arena movement). A fade value trunc((1 − p) × 128) is kept, where p is the animation's progress from 0 to 1 (Low: the effect's use of it). The gust connect test runs each tick while the attack's hit flag is clear (see Gust connect test). When animation 7 finishes, the boss's arena points are updated: the current point takes the next point, the previous point takes the old current point, and the next point is cleared (High). The arena-movement step later in the same tick already places the boss on the new point, so from the next tick bone 6 is there.
- **Sub-step 2, travel**: animation 22 with animation speed 0 (High), fade 0. Let w = B6 − E. If |w| < 0.5, go to sub-step 3. Otherwise both ends move by 0.5 × w / |w|: the column keeps its length and direction and slides at 0.5 units per tick toward the boss's bone 6, which is now on the new point. So the gust crosses the arena from the old point to the new one. The gust connect test runs here as well while the flag is clear.
- **Vanishing (High).** On the tick clip 7 finishes (the end of sub-step 1, when animation 22 is first requested) and on every tick of sub-step 2, the boss and the companion are each flagged "do not draw this frame" (the flag is cleared by the draw it suppresses, so it lasts one frame per write); on the same end-of-gust tick the boss model extension's emitters are stopped (Placement and reachability, Intended model kind), and on the tick sub-step 2 ends they are restarted. So the beast disappears as its gust leaves, only the column is seen crossing the arena, and the beast reappears on the new point when the run-out starts. Collision and the hero's forced lock-on are unchanged while it is unseen. A rewrite without a companion skips the companion's flag (the original writes it through an empty reference).
- **Sub-step 3, run-out**: animation 22 at the stage's gust speed. The fade value is trunc(p × 128). c falls by 0.25 per tick down to 0. Then E = B6 and O = E + c × f (the column now points from the boss along its facing, with length c). The gust connect test runs each tick while the flag is clear. When animation 22 finishes, go to sub-step 4.
- **Knock-back.** A gust connect deals 20 damage (not blocked, kind 2) and then knocks the hero back: the hero's velocity is set to 7.0 × normalize(−9 f_h + (0, 12, 0)) = (−4.2 f_h.x, 5.6, −4.2 f_h.z), where f_h is the hero's own horizontal forward vector (so the push is away from the hero's facing, not away from the boss), and the hero is sent to action state 48 (the knock-back of SPEC-0036 with K = 7.0, the form SPEC-0015 uses with the reversed hero facing).
- **Sub-step 4, end** (air-flow): the boss returns to idle and draws the air-flow cooldown.

**Rapid air-flow**: with a drawn count k (3 to 5), the attack runs k + 1 gust cycles. After each cycle the boss checks the count before decrementing it. If the count is zero, the attack ends: the boss returns to idle and draws the air-flow cooldown. Otherwise the count drops by one, the next arena point is chosen, and the boss goes back to sub-step 1 (the gust), with no new wind-up. Because c is reset only at the end of the wind-up, a later cycle starts from the c the run-out left (it reaches 0 only if clip 22 is current for 40 ticks or more). Example: k = 2 gives cycles with counts 2, 1 and 0 at the check, so three cycles. Confidence: High.

**Gust connect test (once per decision)**: the gust connect test runs on each tick of sub-steps 1, 2 and 3 while the attack's hit flag is clear. Its first connect deals 20 damage, knocks the hero back and sets the flag. The flag is cleared only when a new decision or reply-roll choice is made, so at most one gust hit lands per decision, however many cycles the rapid attack runs. Confidence: High. The test is the overlap test described in Gust connect shape test. The gust routine exists as two copies (air-flow and rapid air-flow); they are one behavior, except that only the air-flow state steers the boss's facing toward the points (Arena movement).

**Cooldown draw**: all three cooldowns (air-flow, lightning, bouncing) draw a real number u from the stage's minimum to maximum seconds (Random draws), and use ticks = trunc(60 × u). Confidence: High.

### Gust connect shape test

The gust connect test is one call of the shared finite-cylinder overlap of SPEC-0018 (Finite-cylinder overlap, kind 3 routine), which gives every branch, the depth sign and the degenerate cases. Shape A is the hero's body and shape B the gust; the boss's own body takes no part (High).

- **Shape A (hero).** Radius = the hero's body radius (word +0x08 of the hero's motion record); full length H_A = the hero's body height (word +0x0C of the same record); centre = the hero's position plus (H_A / 2) along the up vector; axis = the up vector (0, 1, 0).
- **Shape B (gust).** Radius 6.0 (0x2DA5EC); full length L = |E − O| (equal to the charge value c in sub-steps 1 and 3, and kept unchanged while the column slides in sub-step 2); centre = (O + E) / 2; axis = (E − O) / L, the boss's facing in sub-step 1 and its reverse in sub-step 3.
- **Branch.** The hero axis is vertical and the gust axis is horizontal, so the axes take the general nonparallel rule of SPEC-0018. In that branch the gust, as shape B, acts as a facing card rather than a second round cylinder; the result is asymmetric. Its quirks apply: for example, when the hero's centre lies on the gust's axis line the routine misses the overlap (SPEC-0018 Edge cases).
- **Zero length.** When c has fallen to 0 in sub-step 3, L = 0 and the gust axis is the zero vector. The general branch's facing direction then degenerates and the shared overlap routine finds no connect (High).

The gust connect test uses only the overlap result (true or false); the depth and push direction are not used there. It runs once per decision (see Gust connect test).

### Lightning

- Wind-up is animation 8. The fire phase also plays animation 8. Recovery is animation 10. The source of every bolt is the companion's pose point 1 (0x2DA5E4), not a point of the boss (High).
- **Wind-up time** by stage: stage 1 uses 1.0 s; stage 2 uses 0.5 s; stage 3 sets no new value and keeps the sub-timer as it was (usually 0, so stage-3 lightning fires almost at once). Stage 0 would use 2.0 s, but the stage starts at 1 and only 2 or 3 is ever written, so stage 0 is unreachable. Confidence: High.
- **Beam objects.** A beam is reset by a start call: its drawn length becomes 0, its target length a very large value, and its growth limit 500.0 (0x2DA5F4). Each later set call with a start point and an end point makes the target |end − start|; if the drawn length is below the target by more than 500.0 it grows by 500.0, otherwise it becomes the target (it also shrinks at once). The beam is drawn from the start along the unit direction for the drawn length. "Fully extended" means the target is at most the drawn length. So 500.0 is a growth rate per update and, at arena sizes, beams reach their end in one update (High).
- **Beam activity (High).** A beam is active while the first effect instance made by its start call exists. The start call makes its instances from the beam's effect definition, bound at start-up from definition 447 (both beams); when the definition is missing the start call makes nothing, but it still sets the drawn length to 0, the target to the very large value and the growth limit to 500.0. A set call on an inactive beam does nothing at all: the drawn length and target do not change. The "second beam is not active" tests below use the same flag. Strict-disc consequence (definition 447 is missing): beam 1's drawn length stays 0 and its target stays very large, so the wall sweep never runs (it runs only while the length is above 0), beam 1 is never fully extended, the bolt cylinder has length 0 at the source, and beam 2 is never active, so every reflect candidate only repeats the start call and the special reply can never happen. The lightning is then invisible and harmless, except that a hero body overlapping the zero-length radius-1 disc at the companion's pose point could still register a connect (Medium; the shared overlap with length 0). With stand-in definitions (Test setup) every start makes the beam active at once and the rest of this section applies as written.
- **Start of the fire phase**: when the wind-up ends, beam 1 is reset, the fire timer is set to 3, 2 or 1 s (times 60 ticks) by stage, and the hero's position is written to the boss record (overwritten before use, see Recorded hero position).
- **Aim (each fire tick).** Let P be the hero's position, f_h the hero's horizontal forward vector, u the horizontal unit direction from the hero to the boss and D the horizontal distance between them. The aim point is A = P + (0, 1.5, 0) (the lift is on the vertical lane). If the hero's guard query is true (SPEC-0036; the query other bosses use for blocking) and dot(u, f_h) > 0.75 (the hero faces the boss), A moves 1.65 units along u, toward the boss: the beam then ends at the guarding hero's shield. Beam 1 is set from the source S to A, animation 8 plays, and len is the beam's drawn length; d = (A − S) / |A − S|. Confidence: High.
- **Hits.** The fire timer counts down in ticks. After the wall sweep (Second beam (a)), if the latch is set or fewer than six ticks of the fire phase have elapsed, the tick ends. Otherwise:
  1. **Connect.** The beam is a cylinder of radius 1.0 and full length len, centred at S + 0.5 × len × d (the middle of the drawn beam), with axis d. It is tested against the hero's body cylinder (radius, height and centre as in Gust connect shape test) with the shared overlap of SPEC-0018. Call the result "overlap".
  2. **Guard.** If overlap is true or beam 1 is fully extended, and the hero's guard query is true, and dot(d, f_h) < −0.75 (the hero faces into the beam):
     - with the Fog Mote (item 166, SPEC-0021) in the hero's shield word (word 1 of the hero's Mote words, SPEC-0036), the tick is a reflect candidate (Second beam (b));
     - otherwise the hit is blocked: the hero's take-hit runs with amount 0 and the blocked flag set (so the hero plays the block reaction, SPEC-0036), the latch is set, and no damage follows on this tick.
  3. **Damage.** If the tick is not a candidate, beam 2 is stopped. Then, if overlap is true and the hit was not blocked, the hero takes 10 damage (blocked flag clear, kind 2) and the latch is set.
  So an unguarded hero takes damage only on overlap; a guarding hero who faces the beam is never damaged by it. Confidence: High.

### Second beam (two triggers)

Confidence: High.

Stopping: the second beam stops on a bolt tick that is not a reflect candidate. Ticks that end early (the six-tick gate, a set latch, or a wall bounce) leave it running.

The second beam is reset by either trigger below when it is not active; it is placed (set) on the later ticks of the same trigger.

- **(a) Wall bounce.** On any fire tick, before the six-tick gate, the beam is swept against the level's collision triangles: probe points every 3.0 units along d from S up to len, each point's grid cell, every triangle of that cell tested against the segment from S to A, nearest fraction kept. If a triangle is hit, beam 1 is set from S to S + d × len × fraction. If the second beam is not active it is reset; otherwise it is set from that hit point to the hit point plus v' = v − 2 (v · n) n, where v is the vector from the boss to the hero and n is the unit normal of the hit triangle. The tick ends there, so a wall-hit tick cannot damage the hero.
- **(b) Reflect candidate.** Let K = S + len × d (the end of beam 1, the aim point when the beam has reached it). If the second beam is not active it is reset and the tick ends (no damage, no latch change). Otherwise the second beam is set from K to R = P + (D + 5.0) × f_h + (0, 4.0, 0): out of the shield along the hero's facing, 5 units past the boss's distance and 4 units up. If dot((R − K) / |R − K|, u) > 0.99, the boss enters the special-reply state: the reply animation is drawn (15 or 16 by a fair coin) and both beams stop. There is no offset along the boss's facing.
- **Reflect geometry.** With the hero facing the boss exactly, on level ground and with the beam at full length, the vertical gap between K and R is 2.5 and the horizontal run is D + 3.35, so the dot is (D + 3.35) / sqrt((D + 3.35)² + 6.25). It exceeds 0.99 only for D greater than about 14.2. Closer than that the reflection never counts; farther away, the hero must face the boss within about 5 degrees (Medium for the angle, which depends on the heights).

### Recorded hero position

At fire start the hero's position is written as a four-word vector into the boss record (word indices 0x13C to 0x13F). On every fire tick the aim point is computed and written to the same words before they are read, and only the lightning fire phase reads them. So the value written at fire start has no effect. Confidence: High.

### Special-reply state (state 7)

- Entered only from a reflect candidate as above. Both beams are stopped on entry.
- Until the chosen animation (15 or 16) is current, the boss requests it every tick (the companion gets the same request), makes itself the target of the monster name and health bar for 10 s (SPEC-0023; the same step as SPEC-0038 Behavior 37 step 3) and plays the common hit spark (effect group 3, id 222) at a hit point on its body. Normally this is one tick. When it is current and has finished, the boss takes 20 damage (special-reply damage tunable) through the shared HP subtraction: if 20 is below the boss's HP (HP field at offset 0x154 of the entity record) it is subtracted; otherwise HP becomes 0 and the entity's death method runs. Then the entity's refresh method runs (it does nothing). Then the reply roll, also when the HP has just reached 0; the tail of the tick then puts the base state back to 1 (Phases and death).
- The same subtraction is used by the shared NPC take-hit and by the hero's take-hit, so a reply hit counts like any other HP loss for the stage rule. The reply calls the subtraction directly, so the shared take-hit's damage doubling does not apply to it. The shared NPC hit method still exists on the object, but no hero attack reaches it: the hero's scans accept only targets that pass the hittable test, and the controller keeps the boss's invulnerable word at 1 outside the reaction state and its base state at 20 (guard) inside it (Hurt side). So the reply is the only HP loss (High).
- The reaction trigger is still evaluated in this state, so a reaction can replace the reply before the damage lands (High).

### Bouncing balls

- **Spawn.** Each ball takes a free slot of the 5-slot pool; with no free slot it is not spawned. Its slot requests particle definition 450, which is absent (Placement and reachability). Position (and previous position) = the boss's position + 2.0 × f, where f is the boss's forward vector. Horizontal direction = normalize((1 − r) × f + r × p), where r is a real draw from −0.5 to 0.5 and p = normalize(f × up), the horizontal perpendicular. The blend is lopsided: r = 0.5 turns the ball 45 degrees to one side, r = −0.5 about 18.4 degrees to the other. Horizontal speed = ball speed / 60 per tick (10 units per second). Vertical velocity 1.0, travel 0.
- **Each tick, in order:** position += direction × horizontal speed; position.y += the current vertical velocity; vertical velocity −= 0.1 (gravity per tick).
- **Falling ticks only** (vertical velocity now below 0): g = the ground probe at the ball with ceiling 8 (SPEC-0018). If position.y ≤ g − 1.0, the ball bounces: direction = normalize((1 − |r|) × direction + r × perpendicular), r a real draw from −0.9 to 0.9, and vertical velocity = 1.0. Then travel += the horizontal distance from the previous position to the current one, and the previous position becomes the current one. If travel > 50 (0x2DA5C0), the ball despawns with a burst effect. Because the previous position is updated only on falling ticks, travel sums to the horizontal path length; at 10 units per second a ball lasts about 5 s.
- **No restitution.** Horizontal speed never changes and every bounce launches at 1.0 per tick. From a bounce at 1.0 with gravity 0.1 per tick the apex is 5.5 units above the bounce point (sum of 1.0 − 0.1k for k = 0 to 9). Confidence: High.
- **Touch** (every tick, once per ball): the hero's body cylinder (radius, height, base at the hero's position, up axis) is tested against a sphere of radius 2.0 at the ball. On a touch the ball despawns and the hero takes 50 damage (no attacker id, kind 2). The ball code requests group-3 effect 451 on touch and range expiry, but that definition is absent from the disc's effect library, so no particle burst is created by the normal lookup path; its intended appearance is unknown.

### Lightning hit latch

- During the fire phase the latch is cleared on each tick where the remaining count is a multiple of 60. The countdown runs before the state, so the first fire tick already shows the fire time minus 1: in stage 1 (180 ticks) the clears seen are at 120 and 60, in stage 2 (120 ticks) at 60, and in stage 3 (60 ticks) none. The first window relies on the latch cleared by the decision. With the six-tick gate, at most 3 hits land in stage 1, 2 in stage 2 and 1 in stage 3. Confidence: High.

### Reaction state

- When the trigger is true on a tick of this state, animation 23 is requested and the hold is set to trunc(60 × 1.5) = 90 ticks. On a tick with the trigger false, a hold above 0 drops by 1; at 0 the reply roll runs. Both beams were stopped on entry. While the state lasts, the boss and the companion are in base state 20 (the guard stance, written by the tail of each tick), so the hero's swing and shots still test them and are blocked or bounced without damage (Hurt side). The 1.5 s hold restarts only on ticks on which the trigger is true; the animation request is repeated on those ticks.

### Hurt side (High)

- **Hittable test.** The hero's swing, Roberta's shots, the Mote objects, the charm walks and the random target finder take a character only when its hittable query passes: base state not 16, 33, 36, 53 or 54, and the invulnerable word (+0x7F0) clear (SPEC-0036, Hittable predicate). The Cloud Beast controller sets the invulnerable word to 1 on the boss and on the companion in the tail of every tick whose state is not 8 and never clears it. Both bodies are therefore skipped by all of those scans for the whole fight. The controller has no hit routine of its own (the bosses that test the hero's swing in their own routines do so for this reason), so no hero attack can reduce the boss's 240 HP or the companion's 50 HP.
- **Guard window.** In state 8 the tail writes base state 20 instead. The swing and shot scans also test a target that is not hittable but guarding (SPEC-0036, Hit detection): a non-power swing is blocked when the dot product of the target's facing and the hero's facing is below the row's Blocking Angle (0 on rows 1 and 2, so only swings made roughly against the target's facing are blocked and others do nothing); a power swing and a full-release shot do nothing; a quick shot bounces off (the deflect flag is clear). No damage results from any of them. These tests need the target's bones to have hurt capsules of positive length, which the missing rig cannot confirm.
- **Hero lock-on.** While the companion exists the controller writes its own character id into the hero's forced lock-on word on every tick, the same write the Werelupe King and the Black Knight make (SPEC-0040, Behavior 20). Both bodies are otherwise ordinary lock-on candidates. The boss and the companion both have the body-push flag cleared on every tick, so neither pushes the hero or is pushed.
- **No other damage.** Nothing else lowers the boss's HP. The special reply (20 per reply) is the only way; with the stage thresholds the HP trace is 240, 220, 200, 180, 160 (stage 1), 140 to 80 (stage 2, after 5 to 8 replies), 60 down to 0 (stage 3, after 9 to 12 replies), then 0 for every later reply (the boss does not die, Phases and death).

## Edge cases and error handling

- **Band rule with cooldowns** (reproduce it): a cooling-down air-flow band does not drop out of the roll. Its rolls fall through to lightning, and a cooling lightning band lowers the lightning share and lets the rest fall to bouncing (see Deciding). Do not treat a blocked band as a weight of 0.
- **Latch tied to the counter** (High): the once-per-window limit is a fixed clock, so two hits can land within a few ticks of each other across a multiple of 60. Reproduce the counter rule, not a rolling one-second window.
- **Wind-up quirk** (reproduce it): stage 1 uses the 1.0 s wind-up stored in the table, stage 2 uses 0.5 s, and stage 3 sets no new wind-up; it keeps whatever the sub-timer held, which is usually 0, so stage-3 lightning fires almost at once. Confirmed (High).
- Stage-3 hesitation uses the stage-2 range (0.5–1.0 s).
- **Rapid cycles restart at the gust**: the second and later rapid cycles begin at sub-step 1, with no new wind-up.
- **Gust hit once per decision**: later cycles and sub-steps deal no new gust damage until a new decision is made (see Gust connect test).
- **Missing arena points** (High for the original's behaviour): for each missing locator the original prints two debug messages (the second says the behaviour will probably fail) and stores an empty point. Arena movement then reads the current point's position through that empty reference, which has no defined result. A rebuild should leave the boss where it was spawned, with its facing unchanged, and still run the attacks.
- **Missing companion** (High): see Test spawn walkthrough. A rebuild should skip the lightning fire phase and Roberta's reaction mode while no companion exists.
- **Reaction interrupts attacks** (High): the reaction check can replace any state except air-flow and rapid air-flow. It stops both lightning beams and skips the interrupted handler that tick. If lightning or bouncing bolts are interrupted, their cooldown is not assigned because each cooldown is drawn only on the normal recovery or animation-complete exit. Bouncing balls spawned before the interruption keep updating and can still hit during reaction; if interruption occurs before animation event 32, no balls spawn. If reaction interrupts shock, the normal stop call is skipped; whether any visible effect persists cannot be established because its definition is absent. This is controller behavior; the intended balance effect is unknown.
- **Shock fallback does not reset hesitation** (High): entering shock from an idle decision leaves the hesitation timer at zero. When shock ends, the next tick decides immediately; if no weighted attack is chosen and the hero is still within range, shock can repeat without a fresh wait. Choosing a weighted attack follows its usual timer reset.
- **Stage sampling during attacks** (High): the stage is recalculated every tick, but attack parameters are read at different points. Hesitation and lightning wind-up are chosen on attack selection; lightning fire duration is chosen when wind-up ends. Gust speed is read during gust/run-out ticks, and the air-flow cooldown is drawn on exit using the then-current stage. Ball count is read at the animation event, ball speed at each ball spawn, and bouncing cooldown at normal animation completion using the then-current stage. Lightning cooldown is likewise drawn on normal recovery completion using the current stage. Reaction interruption can skip those cooldown draws (above).
- **Interrupted reply** (High): the reaction trigger can end the special reply before its 20 damage.
- **Beam activity** (High): with no beam effect definition the beams never become active and the lightning cannot hit, be blocked or reflect, so the boss's HP never falls (Lightning, Beam activity). A rewrite that runs the designed fight binds stand-in beam effects.
- **Debug display**: the original keeps a debug text line with the state name, HP, rounded distance and stage; only states 0 to 6 have names (idle, shock attack, combat fidget, air-flow attack, rapid air-flow attack, lightning attack, bouncing bolt attack, in that order, which confirms the state numbering above); the distance shown is the same distance value the shock check uses, rounded to the nearest whole number. The missing names suggest the reply and reaction states were added later. Not needed for play.
