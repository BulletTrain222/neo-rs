## Summary

This spec describes the level script modules of 11 world packs: 1217, 991, 934, 1163, 777, 1300, 842, 758, 909, 1098 and 1023. They are the 11 largest of the 23 modules assigned to this spec group, measured by the sum of function sizes. The 12 smallest of the same 23 are covered by SPEC-0044.

All eleven export Init, Update and Exit, and all eleven are Exterior-family modules. No payload in this spec repeats another payload in the archive.

The modules use the host API catalogue of SPEC-0030 and the trigger, thread and slot rules of SPEC-0030 and SPEC-0032. Most are built from the same parts as the other specs: a proximity dialogue routine that picks one line by a cascade of game flags, a teleport routine that offers a button prompt and then starts an interior or exterior entry, an activate-world routine that resets a blackboard value, slot loads chosen by flags, and scripted cutscenes made of fades, camera tracks, letterbox and walks. Several modules (909, 1098, 1163) also drive the shared entity-control routine, whose rules and records are in SPEC-0043 (section "Shared entity-control routine").

Slot rule used throughout: SlotCreate loads nothing. It reserves a buffer for the next slot number and returns that number, or -1 when no slot is free (SPEC-0030 row 207). Even with an empty array it reserves a small base buffer and uses a slot number. A module that stores that return value and passes it to SlotLoad loads into a real slot. Every slot call (SlotLoad, SlotReset, SlotCharacterCount) with a slot outside the valid range, including -1, does nothing; a SlotLoad with -1 returns 0 after one wait step (SPEC-0030 rows 205, 208 and 216). Some module data words in this spec hold slot numbers that Init stores from SlotCreate results: 1163 four module data words, and the other words listed under Edge cases. One module data word of 842 is stored by Init from a SlotCreate result in play, with no branch between the call and the store (High for the store). Before Init stores it, the word holds -1 (its value in the file), so calls through it do nothing; after Init it names the slot that SlotCreate returned. Calls through them act on that slot when the stored result is a slot number. The five slot words of 1098 are stored by Init in play from SlotCreate results (Open question 16, resolved; see the 1098 section). The slot arguments of 758, 991 and 1023 that are not module words are not resolved, so this spec states no slot number for them (Open question 15).

The registration tables of 1023 and 758 are complete (see their sections); that of 1098 is incomplete, and its gaps are listed under Open questions. Reachability in this spec is static: it follows the calls and registrations in the code. Flag gates decide whether a reached routine runs in play. Times are seconds unless marked as ticks. Sleep(n) yields n ticks; Wait(s) yields about s x 60 ticks (SPEC-0030, Open question 1). Notation follows SPEC-0043: "flag N" is a game flag, "item N" a world item id, "object N" an animated object id, "entity N" an entity id, "line N" a dialogue line id of the world's text, "set N" a character region index passed to a slot load, "eW N" a world identifier, "locator N" a locator id, "track N" a camera track id, and "fade black" a colour of zero values. "Set" for a flag means non-zero. "LevelMsg(line N, bracket)" means the line is shown with the conversation bracket; "talk" means the conversation target is set, the line is shown, and the conversation is ended.

Proximity line tables. Every proximity routine uses the talk frame of SPEC-0022 (Conversations): it picks at most one line index, then runs SetConversationTarget(the talked entity, 1), LevelMsg(line, wait) and EndConversation; when it picks no line, nothing happens at all ("silent": no conversation starts). Prompt lines inside a routine are shown without a conversation target. The tables give line indices only, with this notation (the rotation patterns are those of SPEC-0022): conditions are tested in the order listed and the first that holds wins ("else" continues the list); a flag number alone means "that flag is set"; "x/y" means line x when Tor (hero 0) is active and line y when Roberta (hero 1) is; "a-c" or "a, b, c" means those lines in turn on successive talks, then again from a; "a; then b, c" shows a once and then cycles b, c; "a, b" alternates two lines; "a, b, then silent" shows two lines and then nothing until the branch changes. The rotation counter belongs to the routine, so the entities that share a routine share one sequence, and it restarts when the routine takes a different branch, except in routines marked "shared counter", which keep counting across branches. The counters are module data (Edge cases, module data lifetime).

Where a call argument is taken from a record field or from module data it is written as "from record" or "from module data", and the value is not given. Where an argument could not be resolved from the static reach it is written "unknown".

Routines are named by role in this spec (for example "proximity routine", "teleport routine", "trigger routine", "thread") because the module's own routine names are not part of the clean-side vocabulary. Routine and helper numbers are local to this spec.

## Where it lives on the disc

- Each module is the level-script chunk (type 37, "SNR2") of the world pack with the same resource number, as in SPEC-0030 and SPEC-0032.
- Each module's family is the one whose Init name it exports. All eleven are Exterior and export Update and Exit.
- Module data holds slot tables passed to SlotCreate and a few words passed to SlotLoad. Their contents are not copied here.
- Size measure: "code size" in the section headings is the sum of function sizes. It differs from the code sizes in SPEC-0043.
