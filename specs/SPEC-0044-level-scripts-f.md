- Status: Draft
- Disc build: SCUS-97367 v1.00 (same fingerprint as SPEC-0001)
- Confidence: per module (see the Confidence line in each section and the table below). Host call names and argument values: High unless marked. Slot-load activate and keep values: High where the section names them. Slot numbers that a module reads from module data: Medium (see Edge cases). Slot -1: loads and resets with -1 do nothing, Medium-High (in this set of modules only one module data word holds -1 on every path; see Edge cases); whether the host-call path rewrites -1 before the call is open (Open question 1). SlotCreate's return value is the slot number (SPEC-0030 row 207; SPEC-0037 open question 1). Branch conditions: Medium or Low as marked. Unknown values: marked unknown and listed under Open questions.

## Summary

This spec describes the level script modules of 12 world packs: 1393, 745, 1091, 735, 1056, 893, 1327, 1017, 864, 722, 1411 and 1174. They are the 12 smallest of the 23 modules not yet described, by code size. Eleven modules remain for a later spec (listed under "Modules not covered" below). The modules use the host API catalogue of SPEC-0030 and the trigger, thread and slot rules of SPEC-0030 and SPEC-0032.

Slot rule used throughout: SlotCreate loads nothing. It reserves a buffer for the next slot number and returns that number, or -1 when no slot is free (SPEC-0030 row 207). A module that stores that return value and passes it to SlotLoad loads into a real slot. Every slot call (SlotLoad, SlotReset, SlotCharacterCount) with a slot outside the valid range, including -1, does nothing; a SlotLoad with -1 returns 0 after one wait step (SPEC-0030 rows 205, 208 and 216). Several slot stores (module data words that hold a slot number, named as in the notation list below) hold -1 on disc until Init stores a SlotCreate result into them. A call that reads such a store acts on the slot that result names. Where this spec writes a slot as -1, the call reads a slot store that holds -1 in play, so the call does nothing; in this set of modules those stores are slot store B of 864 (never stored, and used only by a debug-only thread, Open question 19), slot store B of 745 while flag 569 is set (module 745 stores that store in play only when flag 569 is clear; slot store A of 745 is stored in play), and slot stores B, C and E of 722 while flag 76 is clear.

Eleven of the twelve are Exterior modules and one (745) is Interior. Each exports Init and Exit. Most also export Update. Eight modules reach host calls from Update (745, 1091, 735, 1056, 1327, 864, 722 and 1411); no host call is reached from Update in 1393, 893, 1017 and 1174. The modules are built from a few parts: entity proximity routines that start a conversation and show dialogue lines chosen by game flags, script triggers with cutscene sequences (fades, camera tracks, hero and entity moves, waits), object setups at Init, control threads that load character slots or run a sequence, teleport and activate-world arrivals, and per-tick checks in Update. A shared entity-record routine (talking, walking and looping animations for the entities in a record table) is called every tick from Update in 722, 745 and 1411 and is summarized at Low confidence; what it does in play depends on which records the module writes.

Times are seconds unless marked as ticks. One tick is 1/60 s (SPEC-0007). Argument conventions follow SPEC-0032: WAIT 0 returns at once, WAIT 1 waits until the action finishes; CONTROL and CAMERA_WAIT values are passed through as the same integers the module passes.

Mapping of notation used below:
- "flag N" is game flag number N, read with the query call and set with the set call. A flag tested "set" is non-zero; "clear" is zero.
- "item N" is a world item id held by the hero. "object N" is an animated object id, "locator N" a locator id, "entity N" an entity id, "line N" a dialogue line id of the world's text, "set N" a slot character set (SPEC-0030), "point N" a navmesh point, "eW N" a world identifier passed to a world call.
- "slot store A of 745" is a module data word that holds a slot number. Stores are named by module and letter; the letters are assigned in the module sections and have no other meaning.
- "dormant" means a routine present in the module that the reachability rules of this spec do not connect to Init, Update, Exit, the load or unload hooks, a registered callback or a thread. Dormant routines are not run (SPEC-0037, SPEC-0043). The load hook runs the module's load-time constructor list (SPEC-0030) at every load, just before Init, so the routines of that list, and the routines they call, are not dormant. Reachability here is static: it follows calls and registrations in the module code and does not evaluate conditions, so flag gates decide whether a reached routine runs in play.
- "routine A", "thread K1" and similar labels are names given in this spec; they have no meaning outside it.

## Where it lives on the disc

- Each module is the level-script chunk (type 37, "SNR2") of the world pack with the same resource number, as in SPEC-0030 and SPEC-0032.
- Each module's family is the one whose Init name it exports (Exterior for eleven, Interior for 745).
- Module data holds slot tables passed to SlotCreate and a few words passed to SlotLoad, teleport and camera tables and navmesh tables. Their contents are not copied here; where a table is used it is named in the module section.

## Repeated payloads

No two of the 163 level-script modules have the same body (compared after removing the header line), so none of the twelve repeats another module. SPEC-0043 lists module 970 as carrying the payload of 956; the module 970 code is not in the set used here, so that repeat is not established.

## Module lists

The sections follow in increasing code size. "Init" means the routine the module exports as its initializer. "Callback" means a routine the module registers for a trigger, a proximity check, an activate-world arrival, a teleport, a breakable, a hero death or an AI player activation. "Thread" means a routine started by ControlThreadStart.

## Edge cases and error handling

- Debug-gated branches: the debug-mode query returns false in this build, so branches under it are never taken in play (SPEC-0030). 745 uses the debug-mode query only inside two helpers that Init calls, where it gates record writes; the calls run in play. 722, 745, 864, 1327 and 1411 each start one control thread whose only work is under the debug query; it does nothing in play. In 1174 the button-driven collision-mask switching of the stage thread is debug-only. A call to the debug query whose result is not tested gates nothing. The play path is as described in each section.
- Dormant routines: each section gives the reachability count for its module. Reachability here is static: it follows calls and registrations found in the module code and does not evaluate conditions. Flag gates decide whether a reached routine runs in play. A routine that is not reached is not run. Registered trigger and thread bodies are reached, not dormant.
- Unknown arguments: a call argument marked unknown in a section has no value that was found on every path. Where a call site showed a value on some paths and not on others, the section says so. Slots marked unknown in a section are still not guessed.
- Slot id -1: -1 names no slot. A SlotLoad with -1 returns 0 after one wait step, and nothing is torn down, loaded or spawned. A SlotReset with -1 does nothing. Every load and reset through a store that holds -1 in play does nothing. In this set of modules those stores are slot store B of 864 (never stored; its one reset and one load sit in a debug-only thread, so they do not run in play), slot store B of 745 while flag 569 is set, and slot stores B, C and E of 722 while flag 76 is clear (Medium-High). These follow SPEC-0030 rows 205 and 208 (Medium-High for the runtime; whether the host-call path rewrites -1 is Open question 1). Every other slot store in this set of modules is stored by Init in play, except slot store B of 745, which is stored only when flag 569 is clear, and slot stores B, C and E of 722, which are stored only with flag 76 set.
