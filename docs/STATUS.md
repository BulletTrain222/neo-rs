# Project status — 2026-10-25

## Implemented

- Rust workspace with neopets-data, neopets-sim, neopets-app, and a local Git repository (no remote).
- Read-only ISO9660 indexing, serial/version and executable-header checks, bounded file/range reads.
- Explicit ordered mod-file resolution with disc fallback and path containment checks.
- Engine-independent simulation boundary. Only a scaffold tick counter; no original gameplay.
- Bevy 0.19.1 status window with 3D/UI features enabled for later viewers.
- **Range-read hardening (groundwork, no spec):** `Disc::stream_range` feeds any file range to a callback in bounded chunks with one reused buffer; whole-tree caps on indexing (65,536 files, 64 MiB of directory data); I/O errors after indexing (e.g. image truncated) report offset and length. `read`/`read_range` share one bounds check.
- **Fingerprint plumbing:** `neopets_data::fingerprint` streams SHA-256 over any disc file (`sha2` 0.10 crate), compares against an expected digest, and parses 64-digit hex. The inspector takes `--sha256 <disc file>` (repeatable). SPEC-0001's boot-program digest is now enforced by the archive index.
- **Fixed-timestep loop (groundwork, no spec):** `neopets_sim::FixedStep` converts host-supplied elapsed nanoseconds into whole ticks with an exact integer remainder (no drift at 60 Hz), caps catch-up per call and counts dropped ticks, and gives an interpolation alpha. `Simulation::run_for` runs the due ticks with one input. The app samples WASD/arrows/left stick into `PlayerInput` (movement only, buttons unmapped), steps the sim, then draws a diagnostic HUD. The 60 Hz rate and 8-tick catch-up cap are placeholders pending R-0007.
- **M2 archive access (SPEC-0001, SPEC-0002):** `neopets_data::archive::ArchiveIndex::from_disc` requires the boot program's SHA-256 to match SPEC-0001, maps the index table's virtual address to a file offset through the ELF program headers (`elf.rs`, public ELF format), reads the 1434 entries, and checks invariants 1–4 (starts at 0, contiguous, covers GAMEFILE.DAT exactly, 76 empty). Resources are read by number with range checks; empty placeholders read as no bytes. `neopets_data::resource` classifies families by first bytes and walks IDM chunk chains (stop on type 0, buffer end, or an implausible header; one-chunk limit for texture packs and 544–575). The inspector gains `--resource <n>`, `--resources` (survey of every resource), and `--coverage` (writes private/asset-coverage.txt; every decoded count is 0 until decoders land).
- **M3 textures (SPEC-0003, partly):** `gsmem.rs` emulates 4 MiB of GS local memory with PSMCT32, PSMT8 and PSMT4 addressing (public GS documentation); `texture.rs` parses type-4 chunks, uploads the pixel block at the segment's base (so front-end absolute addresses work), and decodes indexed textures through 256-colour (CSM1 order) or 16-colour palettes with GS alpha (A × 2, capped). `material.rs` parses shader lists (type 2), reads each group's pass-0 TEX0 from its state block, and resolves texture and palette inside texture chunk k, as SPEC-0003 specifies. Not implemented from SPEC-0003: flipbooks, UV modes, CPU vertex animators, blend/test/filter state, billboards, residency, the pass-1 texture context, nested shader lists in model-set wrappers.
- **Resource browser and texture viewer:** picks a resource number (type digits + Enter, `[`/`]` ±1, PgUp/PgDn ±100, or `--resource N` at start), clamped to the index, and shows its sectors, size, family, and chunk-type chain. Its decoded textures appear on the 3D quad, sized to their aspect ratio; `,` and `.` cycle them. Textures under a shader list are shown once per material pairing; front-end pictures (no shader list) use their single palette. Tone mapping is off so stored colours show unchanged.
- **M4 models (SPEC-0004, partly):** `mesh.rs` walks node trees (group, visibility, distance-cull and leaf nodes; link, bounds and cycle checks) and decodes one-packet leaves: the packet header (one or two GIF tags), the VIF stream (STMASK, UNPACK V3-32/V2-32/V4-8/masked S-8, MSCNT, tag records), layouts A (skinned), B (plain) and C (lit), two-pass UV halves, and the strip rule. `model.rs` finds trees in standalone type-13/12 chunks, type-8 container children, type-3 level trees and type-18 model-set wrappers, and builds indexed triangle lists with each leaf's material: texture decoded at the TEX0 sampling size, CLAMP wrap modes, and vertex colours scaled per the pass-0 program (16 = 1.0 for lit programs, 128 = 1.0 for unlit). Held-item models 544–575 use resource 7's shader list. Not implemented: pass 1 of two-pass materials, blend/alpha-test state (alpha is masked at 0.5), distance and visibility culling, type-29 placed objects and type-20 instances (M6), type-33 shadow blocks, attach points, the 13 CPU-animated water leaves (packet kind 1).
- **World scenes (SPEC-0004 placement layouts; SPEC-0006 loader table):** `world.rs` collects a world pack's level display trees (type 3, world space), placed objects (type 29: inline type-12 tree and column-major matrix at +0xC0) and instanced meshes (type 20: inline tree and 0x50-byte instance matrices), skipping references that do not resolve. `model::build_world` draws them all with the pack's shader list, baking each matrix into the vertices exactly as stored. Story-layer gating (SPEC-0046 Culling) is applied with the new-game world layer mask 0: type-4 nodes with nonzero layer flags are hidden with their subtrees (this removes Meridell's storm vortex). The sky dome is chosen by the area slot from the boot program's area table (`area.rs`, SPEC-0006 tables A and B behind the fingerprint) and its role-1 layer is drawn at the world origin; the role-10 layer needs an atmosphere zone (type 41) and is not drawn. Not implemented: story flags and SetWorldDisplayMask (the mask stays 0), type-3 display-tree slots and visibility selectors, distance culling, foliage (type 16), ground patches of type-5 model sets, characters, dome UV scroll.
- **M5 animation (SPEC-0005, partly):** `lzo.rs` is an LZO1X decoder written from the public format, with bounds checks and exact-size output. `anim.rs` parses skeleton definitions (types 22–24 and the headerless family headers), the flat type-18 bone table, and clip entries: mode-2 channel streams (constant and animated channels, sample scale 0x3A800EAE), mode-0 frames (÷ 4096), and compressed entries expanded to the plain layout; it samples key pairs (sign flip, componentwise blend, no normalising), combines samples into the pose shown last (replace at full weight, else the φ mix), composes main, sub-part and face families (mask and parent rules, skin bone order) and builds skin matrices W × translate(−rest). `neopets_sim::clip::PlaybackRecord` implements clip start (speed R × 0.5 ÷ S, fade-in), the end rule (one-shot hold; loop wrap keeping the overshoot), key pairs, fractions, φ and progress. The app plays a hero outfit (504–519) with its hero's three families (headers, banks and action tables from SPEC-0005's table), stepping the records once per sim tick and skinning layout-A parts on the CPU each frame; `-` and `=` change the action id (lookup misses give clip 0). Not implemented: root motion (travel), the second main layer, mirrored clips, per-bone translation scale, event bits, secondary-motion chains (Tor's tail, Roberta's head chains), region characters' type-36 animation tables, attach points, crossfade between differently-masked clips beyond the spec rule.
- **Timing (SPEC-0007):** the sim tick is the game's fixed 1/60 s step; catch-up is capped at 4 ticks per frame, and `--original-pacing` caps it at 1 so slow frames slow the game as on the PS2.
- **Ground and spawn (SPEC-0018, SPEC-0006):** `ground.rs` reads the level grid (type 19) and the pack's own type-5 height patches, samples a patch bilinearly per SPEC-0018, and runs the ground probe's accept rule (highest height at or below the ceiling, else the last rejected height, else the miss value; 0.0 with no cell). It reads entry record 0 of the type-11 chunk as the world spawn and applies the spawn height rule (probe from y + 8). Not implemented: inline model sets of placed objects (patch ids other than 0), the runtime candidate gates, the outline-record list test, owner placement. The grid's cell order is taken as x-major by measurement (R-0009).
- **Hero locomotion (SPEC-0033, SPEC-0040; M7 groundwork):** `neopets_sim::hero` implements the stick speed value, the speed tiers (walk mode and R1 run mode with the 30-pass restart wait, tier factors as the play rate), the moving facing turn (0.95 floor), the zeroed step while the stick points behind, and travel by the previous tick's root step through the facing basis, projected onto the ground plane while the gap is below 1.0. Physics (SPEC-0040 Behavior 14A items 5 to 7, `neopets_sim::motion`): the record tick probes 2.5 above the feet for the gap and the ground normal (SPEC-0018's truncated half-sum normal, `Ground::probe_normal`), applies the root travel, the ground constraint, gravity with the gain G, friction 0.6 on the ground, the contacts and the integrator. Air (SPEC-0033 Behaviors 9A and 50): the walk-off check, the Cross jump chooser (states 7 to 10 by stick magnitude, normal y at least 0.82), the launch, air phases 0 to 7 and 10 with their gains, the air steering, the clip tails 76 to 78 and 70 to 67, and the soft, moving and hard landings. Tests reproduce the spec's standing-jump heights, the state-10 drift distances (2.85 and 14.0), the walk-off drops and the walk-off phase timings. `HeroAnim` follows the rate every tick and returns the main layer's root step (doubled while a finished one-shot is held). `neopets-app --play` puts Tor (outfit 504) at pack 909's spawn with a follow camera: WASD or the left stick move, Shift or the right trigger is R1, Space or the south button is Cross (jump), the follow camera turns with the right stick (J/L and I/K on the keyboard) and R is R3. `--autowalk` holds the stick forward for unattended checks; `--autojump` also presses Cross every 120 ticks; `--play-trace <ticks>` runs play mode without a window and prints position, state, air phase, gap and vertical velocity per tick. Box walls: `ground::rectangles` reads the kind-4 and kind-7 rectangle lists (SPEC-0028 6.1) and `neopets_sim::contact` pushes the feet out of every rectangle that passes the box-push gate (class bit 0 or 3, mask 0, positive B extent) with the hero radius 1.175 (SPEC-0040 body size; the 1.25 radius belongs to the camera's eye pass), using SPEC-0018's grown-box test, six face depths, bottom bias, top gate and push distances. Frame-record walls (before the boxes, SPEC-0040 Behavior 14A branch 0): `Ground::frames_at` reads the 0x70-byte frame records named by the cell's entry items (SPEC-0018) with the field layout of SPEC-0033 Behavior 37 (census in 909: every start point lies on its face and run planes with top-plane value H, so a record is a wall of depth H hanging below its top edge), and `WallEdge::push` applies the two-sided ordinary-wall correction r − |a| of SPEC-0018's Petpet pass, gated by a near-vertical face, a run-plane value in (0, L), and feet less than 3.5 below the wall's bottom. Unverified (R-0011): the hero routine's own gates; the 0.25 step height that keeps low edges from blocking is this build's choice; the model-set entry mask and inline (placed-object) model sets are not applied; the ledge-drop and edge acceptance tests and their state hand-offs are not run. Not implemented: cylinders; the corner and preferred-face rules; reverse walk and the backward jump, strafe jumps, air attacks and the plunge, grabs, ledges and every other hero state; the landing event windows; moving platforms and the alternate friction branch; the floor-contact flag; status factors, the eased stationary turn, the displayed-height lag. The stick is applied relative to the screen; the spec's sign is asked about in R-0010.
- **Follow camera (SPEC-0027 mode 0; M7):** `neopets_sim::camera::FollowCamera` runs first in each play tick from the hero's previous pose: the profile chosen by the ground kind (+0x38) of the patch under the hero (`Ground::probe_hit`; kept when there is none), the right-stick stick value and spin input (converter A, D = B⁴ with the 1.3 switch), the target distance (0.65 sin² e), the focus 3.5 above the feet, the spin integrator, the chase and sticky manual elevation with the recentring gate T, the eye on its sphere, the critically damped spring (k 0.085), ground clearance 2.0 above the eye's ground, the eye wall push (frame records other than type 6 and the boxes at radius 1.25) the line-of-sight timer (recentre on the 61st blocked tick) and the R3 recentre (behind, else in front, shrunk by 0.25 while the line is blocked or the candidate is buried). Line tests use `Ground::segment_clear`, SPEC-0018's segment query over the endpoint cells' frame records with type 6 skipped under the restriction flag; the +1.5 endpoint shift is not applied because the spec leaves its coordinate open. The load attach places the eye 10 behind the hero through the pull-in setter. The Bevy view looks from the eye at the focus with SPEC-0027's projection (50.2° vertical, near 1.0); the hero's stick is relative to the camera's rows. Tests reproduce the spec's polar vector, target distances, settle curve, spin rates, chase and manual steps, manual raise and the pull-in vectors. Not implemented: the script override profile, camera-locked states, hold and lean terms, the spring's contact-normal exception, the failure flag and stuck timer, the camera visibility test, side-swing events, scripted plays, shakes and the fade ramp; the eye uses the characters' two-sided wall correction instead of its single-margin plane test (Medium).
- **Overworld streaming (SPEC-0006 World buffers; M7):** `neopets_data::travel` reads the area-pair table, the no-swap list, the block-pair list and the nine family entry names of the host table (SPEC-0030) from the boot program at run time, classifies each pack by the Init entry its module exports (host records 397, 398 and 399 are the Transition, Exterior and Interior Init names: the `--areas` census gives exactly SPEC-0006's 36, 87 and 50 modules, plus the 15 moduleless transitions the spec lists and 3 moduleless exteriors), and reads the tag-0x0B neighbour list (145 tables, position 0 unused and positions 1..m used in all, 528 world ids, as the spec counts). `Ground::cell_value` gives the exit value of the cell under the hero. Play mode starts as the new game does (909 in E current, 691 in T), runs the pending step each tick (neighbour by cell value, tables B and A, area pairs, `neopets_sim::travel::stream_buffer`), loads a streamed neighbour into the other buffer between ticks, and when the current world has no ground under the hero searches the other buffer (when the neighbour-world test passes; the 92-slot swap set and the 15 moduleless transitions are the spec's stated rule members) and swaps worlds on a hit. `sync_worlds` draws the current world, the other world when the neighbour-world test passes, and the current world's sky dome. `--trace-to swap` walks a searched route to the nearest reachable swap point: from the 909 spawn the hero walks onto 691's ground and 691 becomes current with no height jump. Not implemented: doors and teleport landings, interiors, replacement loads, movie returns, kill memory, zone and sound changes on a swap, and the loader's buffer-state checks (a request is read once to learn the pack's kind, which the original knows from its code rule). Stream loads run on a loader thread with its own disc handle (`Disc::reopen`): it reads the pack, classifies it and builds its scene only when the buffer rule will stream it; the window keeps running meanwhile.
- **Doors (SPEC-0006 Doors, Door prompt and confirm, Hero placement, Interior entry steps; SPEC-0028 section 13):** `ground::teleport_planes` reads the teleport plane list (kind-7 rectangles with kind-mask bit 1 and a class other than 500 and 501, in disc order) and `ground::entry_record` the entry records; `Neighbours::arrivals` reads the tag-0x0E arrival list. `BootTravel::imports` matches a module's import names by function name (SPEC-0030 section 2): the `--areas` census finds 169 teleport planes in 102 packs, and the packs whose module does not import RegisterTeleportCallback hold exactly 45 doors, the spec's count of default doors. Those doors work in play: a touched door posts prompt 13 (Enter, while E is current) or 26 (Exit); the chooser shows it on the next tick and E (Square) or the west button confirms; the door then applies the default rule: E to a transition lands on its door (teleport landing, flat and upright forms, reverse flag from the door normal and the hero's forward), E to a non-paired pack enters it as an interior at entry record 0 snapped from 6 above (T released and remembered, E kept), E to a paired exterior replaces E and arrives at the arrival door, T lands on E's door, and I leaves to E's door (upright, probed) and reloads the remembered T. Loads go through the loader thread. Script doors (59 packs import RegisterTeleportCallback) run their level's handler when one is written (below); others do nothing yet. Unverified: the hero's touch test (R-0012); fades, the camera's return to normal and the five idle loader frames are not reproduced. `--trace-to door` stands the hero before door 0, walks in, presses Square on the prompt and goes on through door 0 of each world it reaches twice more.
- **Level behaviour (SPEC-0030 section 7; per-level specs):** `neopets_sim::level` holds the state the level handlers read and write (story flags, the type-and-slot blackboard, held items), an action vocabulary (StartEnterInterior, StartLeaveInterior, MoveHero to an entry record, LevelMsg), and handlers written from the per-level specs: 909's teleport callbacks 0 and 1 (enter slots 72 and 73, prompt 13) and its activate-world routine (round-up flag reset; blackboard value 10, 30, 40 or 50 for slot 68 places the hero at locator 2, 1, 3 or 4, or 28 at stage 6 without item 36; SPEC-0045), 951's teleport callback (line 126 with state 119 set and 122 clear, otherwise message 10 and leave to slot 5; SPEC-0041) and 955's (message 40 and leave to slot 5; SPEC-0032). The `--areas` census confirms 909's entry records 1 to 4 are the spec's locators 1 to 4. Play mode runs a script door's handler on a Square press edge with the confirm flag set and never clears that flag (SPEC-0006 stale confirm), and runs the activate-world routine whenever a world becomes current. Story flags start clear (the new-game flag setup of SPEC-0049 is not applied) and dialogue lines show only their number. Every other level's handlers, and these levels' triggers, talk, threads, slots, objects, cutscenes and Update, are not written yet.
- **Lighting (SPEC-0046 Light slots and the lit draw; Scene default lights):** `light.rs` holds the scene default rig (ambient 50 and three directional lights at strength 0.25) and the lit vertex formula (L = A + Σ clamp(n·T, 0, 1) C; RGB = min(255, L × byte / 16)). Lit parts (programs 1, 2 and 6) are lit at build time in the space they are built in; skinned characters are relit every frame from their skinned normals turned into world space. Not implemented: character light walks over the area's type-30 light sets and dynamic point lights, the 5 % slot ease, the draw colour scale, program 6's specular alpha.
- **Model viewer:** the selected resource's node trees are drawn double-sided and unlit with their materials; the camera frames the model, and the diagnostic grid is hidden while a model is shown. `V` switches between the model and the texture quad. World packs frame on where most geometry is (median vertex and the radius covering 60 % of vertices), and WASD/Q/E (Shift faster) move the orbit target as a fly camera.
- **Inspector:** `--texture <n>` writes the resource's textures as PNGs under private/textures/ (a small built-in PNG writer, `png.rs`), `--materials` resolves and decodes every top-level material on the disc, and `--meshes` decodes every node tree and checks each leaf against its header and bounds.
- **Viewer scaffold (groundwork for M3/M4/M6, no spec):** the app now renders through a 3D orbit camera (drag any mouse button to orbit, scroll to zoom, pitch clamped short of the poles) over a diagnostic grid with X/Y/Z axes, labeled on screen as not game content. Tab hides the HUD. This is viewer tooling, not the original game's camera. Input mapping and the browser picker moved into `neopets-app/src/controls.rs`, orbit math into `orbit.rs`, both unit-tested; Check.cmd now runs `cargo test -p neopets-app` instead of only `check`.
- **GS pixel formats (groundwork for M3, public hardware documentation only):** `neopets_data::gs::decode` turns linear PSMCT32, PSMCT16, PSMT8, and PSMT4 pixels (with 32- or 16-bit palettes, CSM1 or linear) into straight RGBA8, with GS alpha scaling (0x80 = opaque) and TEXA handling for 16-bit alpha. Size-checked (1..=1024 per side), no panics on short input. Not covered: PSMCT24, GS memory swizzled layouts, mipmaps. Whether the game uses any of these, and how, still needs R-0003.
- **Viewer test pattern:** a 64×64 4-bit indexed pattern generated in code is decoded through `gs` and shown on a quad, labeled synthetic. `--screenshot <png>` captures the window after 4 s of real time (render pipelines compile asynchronously, so earlier frames show no meshes), and `--hide-hud` starts with the HUD hidden. The HUD uses ASCII separators because Bevy's built-in font lacks `•` and `—`.
