# Project status — 2026-10-25

## Implemented

- Rust workspace with neopets-data, neopets-sim, neopets-app, and a local Git repository (no remote).
- Read-only ISO9660 indexing, serial/version and executable-header checks, bounded file/range reads.
- Explicit ordered mod-file resolution with disc fallback and path containment checks.
- Engine-independent simulation boundary. Only a scaffold tick counter; no original gameplay.
- Bevy 0.19.1 status window with 3D/UI features enabled for later viewers.
- **Range-read hardening (groundwork, no spec):** `Disc::stream_range` feeds any file range to a callback in bounded chunks with one reused buffer; whole-tree caps on indexing (65,536 files, 64 MiB of directory data); I/O errors after indexing (e.g. image truncated) report offset and length. `read`/`read_range` share one bounds check.
- **Fingerprint plumbing:** `neopets_data::fingerprint` streams SHA-256 over any disc file (`sha2` 0.10 crate), compares against an expected digest, and parses 64-digit hex. The inspector takes `--sha256 <disc file>` (repeatable). SPEC-0001's boot-program digest is now enforced by the archive index.
- **Fixed-timestep loop (groundwork, no spec):** `neopets_sim::FixedStep` converts host-supplied elapsed nanoseconds into whole ticks with an exact integer remainder (no drift at 60 Hz), caps catch-up per call and counts dropped ticks, and gives an interpolation alpha. `Simulation::run_for` runs the due ticks with one input. The app samples WASD/arrows/left stick into `PlayerInput` (movement only, buttons unmapped), steps the sim, then draws a diagnostic HUD. The 60 Hz rate and 8-tick catch-up cap are placeholders pending R-0007.
- **M2 archive access (SPEC-0001, SPEC-0002):** `neopets_data::archive::ArchiveIndex::from_disc` requires the boot program's SHA-256 to match SPEC-0001, maps the index table's virtual address to a file offset through the ELF program headers (`elf.rs`, public ELF format), reads the 1434 entries, and checks invariants 1–4 (starts at 0, contiguous, covers GAMEFILE.DAT exactly, 76 empty). Resources are read by number with range checks; empty placeholders read as no bytes. `neopets_data::resource` classifies families by first bytes and walks IDM chunk chains (stop on type 0, buffer end, or an implausible header; one-chunk limit for texture packs and 544–575). The inspector gains `--resource <n>`, `--resources` (survey of every resource), and `--coverage` (writes private/asset-coverage.txt; every decoded count is 0 until decoders land).
- **M3 textures (SPEC-0003, partly):** `gsmem.rs` emulates 4 MiB of GS local memory with PSMCT32, PSMT8 and PSMT4 addressing (public GS documentation); `texture.rs` parses type-4 chunks, uploads the pixel block at the segment's base (so front-end absolute addresses work), and decodes indexed textures through 256-colour (CSM1 order) or 16-colour palettes with GS alpha (A × 2, capped). `material.rs` parses shader lists (type 2), reads each group's pass-0 TEX0 from its state block, and resolves texture and palette inside texture chunk k, as SPEC-0003 specifies. Not implemented from SPEC-0003: flipbooks, UV modes, CPU vertex animators, blend/test/filter state, billboards, residency, the pass-1 texture context, nested shader lists in model-set wrappers.
- **Resource browser and texture viewer:** picks a resource number (type digits + Enter, `[`/`]` ±1, PgUp/PgDn ±100, or `--resource N` at start), clamped to the index, and shows its sectors, size, family, and chunk-type chain. Its decoded textures appear on the 3D quad, sized to their aspect ratio; `,` and `.` cycle them. Textures under a shader list are shown once per material pairing; front-end pictures (no shader list) use their single palette. Tone mapping is off so stored colours show unchanged.
- **M4 models (SPEC-0004, partly):** `mesh.rs` walks node trees (group, visibility, distance-cull and leaf nodes; link, bounds and cycle checks) and decodes one-packet leaves: the packet header (one or two GIF tags), the VIF stream (STMASK, UNPACK V3-32/V2-32/V4-8/masked S-8, MSCNT, tag records), layouts A (skinned), B (plain) and C (lit), two-pass UV halves, and the strip rule. `model.rs` finds trees in standalone type-13/12 chunks, type-8 container children, type-3 level trees and type-18 model-set wrappers, and builds indexed triangle lists with each leaf's material: texture decoded at the TEX0 sampling size, CLAMP wrap modes, and vertex colours scaled per the pass-0 program (16 = 1.0 for lit programs, 128 = 1.0 for unlit). Held-item models 544–575 use resource 7's shader list. Not implemented: pass 1 of two-pass materials, blend/alpha-test state (alpha is masked at 0.5), distance and visibility culling, type-29 placed objects and type-20 instances (M6), type-33 shadow blocks, attach points, the 13 CPU-animated water leaves (packet kind 1).
- **World scenes (SPEC-0004 placement layouts; SPEC-0006 loader table):** `world.rs` collects a world pack's level display trees (type 3, world space), placed objects (type 29: inline type-12 tree and column-major matrix at +0xC0) and instanced meshes (type 20: inline tree and 0x50-byte instance matrices), skipping references that do not resolve. `model::build_world` draws them all with the pack's shader list, baking each matrix into the vertices exactly as stored. Story-layer gating (SPEC-0046 Culling) is applied with the new-game world layer mask 0: type-4 nodes with nonzero layer flags are hidden with their subtrees (this removes Meridell's storm vortex). The sky dome is chosen by the area slot from the boot program's area table (`area.rs`, SPEC-0006 tables A and B behind the fingerprint) and its role-1 layer is drawn at the world origin; the role-10 layer needs an atmosphere zone (type 41) and is not drawn. Not implemented: story flags and SetWorldDisplayMask (the mask stays 0), type-3 display-tree slots and visibility selectors, distance culling, foliage (type 16), ground patches of type-5 model sets, characters, dome UV scroll.
- **M5 animation (SPEC-0005, partly):** `lzo.rs` is an LZO1X decoder written from the public format, with bounds checks and exact-size output. `anim.rs` parses skeleton definitions (types 22–24 and the headerless family headers), the flat type-18 bone table, and clip entries: mode-2 channel streams (constant and animated channels, sample scale 0x3A800EAE), mode-0 frames (÷ 4096), and compressed entries expanded to the plain layout; it samples key pairs (sign flip, componentwise blend, no normalising), combines samples into the pose shown last (replace at full weight, else the φ mix), composes main, sub-part and face families (mask and parent rules, skin bone order) and builds skin matrices W × translate(−rest). `neopets_sim::clip::PlaybackRecord` implements clip start (speed R × 0.5 ÷ S, fade-in), the end rule (one-shot hold; loop wrap keeping the overshoot), key pairs, fractions, φ and progress. The app plays a hero outfit (504–519) with its hero's three families (headers, banks and action tables from SPEC-0005's table), stepping the records once per sim tick and skinning layout-A parts on the CPU each frame; `-` and `=` change the action id (lookup misses give clip 0). Not implemented: root motion (travel), the second main layer, mirrored clips, per-bone translation scale, event bits, secondary-motion chains (Tor's tail, Roberta's head chains), region characters' type-36 animation tables, attach points, crossfade between differently-masked clips beyond the spec rule.
- **Timing (SPEC-0007):** the sim tick is the game's fixed 1/60 s step; catch-up is capped at 4 ticks per frame, and `--original-pacing` caps it at 1 so slow frames slow the game as on the PS2.
- **Ground and spawn (SPEC-0018, SPEC-0006):** `ground.rs` reads the level grid (type 19) and the pack's own type-5 height patches, samples a patch bilinearly per SPEC-0018, and runs the ground probe's accept rule (highest height at or below the ceiling, else the last rejected height, else the miss value; 0.0 with no cell). It reads entry record 0 of the type-11 chunk as the world spawn and applies the spawn height rule (probe from y + 8). Not implemented: inline model sets of placed objects (patch ids other than 0), the runtime candidate gates, the outline-record list test, owner placement. The grid's cell order is taken as x-major by measurement (R-0009).

Unverified (R-0011): the hero routine's own gates; the 0.25 step height that keeps low edges from blocking is this build's choice; the model-set entry mask and inline (placed-object) model sets are not applied; the ledge-drop and edge acceptance tests and their state hand-offs are not run. Not implemented: cylinders; the corner and preferred-face rules; reverse walk and the backward jump, strafe jumps, air attacks and the plunge, grabs, ledges and every other hero state; the landing event windows; moving platforms and the alternate friction branch; the floor-contact flag; status factors, the eased stationary turn, the displayed-height lag.
